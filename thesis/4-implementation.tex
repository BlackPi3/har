\section{Model Architectures}
\label{sec:architectures}

Our framework comprises four primary neural network components: the feature extractor, activity classifier, pose-to-IMU regressor, and discriminator. Each component is designed with configurable hyperparameters to enable systematic architecture search.

\paragraph{Feature Extractor.}
The feature extractor $F$ transforms raw accelerometer signals into fixed-dimensional feature representations suitable for classification. We adapt the encoder portion of the convolutional autoencoder architecture from MM-Fit \cite{stromback2020mm} as our feature extractor, using 1D convolutions that operate along the temporal axis while treating the three accelerometer axes as input channels. It maps an accelerometer window $\mathbf{a}\in\mathbb{R}^{3\times T}$ to an embedding $\mathbf{z}\in\mathbb{R}^{d}$ using a stack of strided temporal convolutions, optional pooling, and a final linear projection. \Cref{tab:fe-params} reports the hyperparameters and their default values. Linear layers use Kaiming Normal initialization \cite{he2015delving} for LeakyReLU-based networks.

\paragraph{Pose-to-IMU Regressor}
The regressor $R$ transforms skeleton pose sequences into simulated accelerometer signals. We adopt the architecture proposed by Rey \textit{et al.} \cite{fortes2021translating}. Compared to the original formulation which predicts a single sensor channel at a time, our implementation predicts the full 3-axis accelerometer window jointly. The regressor consumes a pose window $\mathbf{p} \in \mathbb{R}^{C_{\text{in}} \times J \times T}$ and outputs a simulated accelerometer window $\tilde{\mathbf{a}} \in \mathbb{R}^{3 \times T}$ using a residual Temporal Convolutional Network (TCN): joint-temporal blocks operate on the input using dilated convolutions, followed by a temporal aggregation block and a final projection. \Cref{tab:regressor-params} summarizes the hyperparameters.

For adversarial training scenarios, we implement discriminators that distinguish real from simulated data. Two variants exist depending on whether discrimination operates at the feature level or signal level.

\paragraph{Feature-level Discriminator}
The feature-level discriminator $D_F$ is an MLP that takes encoder embeddings and outputs a single real/fake logit, optimized with binary cross-entropy loss. Its input is passed through a Gradient Reversal Layer (GRL), enabling end-to-end adversarial training with a single backward pass. When the ACGAN variant is enabled, the discriminator additionally outputs auxiliary activity logits. \Cref{tab:df-params} summarizes the hyperparameters.

\paragraph{WGAN-GP Training.} For signal-level adversarial training we use WGAN-GP \cite{arjovsky2017wasserstein, gulrajani2017improved} with gradient penalty (default $\lambda_{\text{GP}}=10$) and alternating updates ($n_{\text{critic}}=5$ critic steps per regressor step by default). We omit the full objective here because the adversarial losses are defined in the Method chapter; in this chapter we focus on implementation choices and default hyperparameters.

\paragraph{ACGAN Variant.} We optionally extend the discriminator with class conditioning following the Auxiliary Classifier GAN (ACGAN) framework \cite{odena2017conditional}. In this variant, the discriminator also outputs auxiliary activity logits. The auxiliary head is trained with cross-entropy on both real and simulated samples, and the same auxiliary loss is included in the regressor update for simulated samples, encouraging class-conditional realism.

\paragraph{Staged Training.} To prevent the regressor from receiving adversarial gradients before learning basic signal structure, we optionally pretrain for $E_{\text{pre}}$ epochs using only MSE loss before enabling adversarial training. This staged approach helps establish reasonable signal quality before the discriminator begins providing feedback.

\paragraph{Gradient Reversal Layer}
For the feature-level discriminator (Scenario 4.1), we use a Gradient Reversal Layer (GRL) \cite{ganin2016domain} to enable end-to-end adversarial training in a single backward pass. The GRL is the identity in the forward pass but multiplies upstream gradients by $-\lambda$ in the backward pass. $\lambda$ can be fixed or scheduled by the trainer.

Note that the signal-level discriminator (Scenario 4.2) does not use GRL; it uses WGAN-GP with alternating critic/regressor updates instead.

\section{Training Pipeline}
\label{sec:pipeline}

All scenarios are implemented in a single configurable training script. Configuration flags control which components are instantiated (e.g., separate feature extractors or classifiers) and which losses are active, so each scenario corresponds to a specific configuration rather than separate code.

Each training batch evaluates two computational paths:
\begin{itemize}
    \item \textbf{Real path}: $\mathbf{a} \rightarrow F \rightarrow \mathbf{z}_{\text{real}} \rightarrow C \rightarrow \hat{y}_{\text{real}}$
    \item \textbf{Simulated path}: $\mathbf{p} \rightarrow R \rightarrow \tilde{\mathbf{a}} \rightarrow F_{\text{sim}} \rightarrow \mathbf{z}_{\text{sim}} \rightarrow C_{\text{sim}} \rightarrow \hat{y}_{\text{sim}}$
\end{itemize}
where by default $F_{\text{sim}} \equiv F$ and $C_{\text{sim}} \equiv C$. When signal-level WGAN-GP adversarial training is enabled (Scenario~4.2), we use alternating optimization ($n_{\text{critic}}$ critic updates per generator update); all other scenarios use a single backward pass.

During validation and testing, only the real path is evaluated:
\begin{equation}
    \hat{y} = \arg\max_k [C(F(\mathbf{a}_{\text{real}}))]_k
\end{equation}
All model selection---early stopping, best checkpoint retention, and hyperparameter optimization---is driven by validation macro~F1 computed on this real-only path. Training hyperparameters including learning rate scheduling (linear warmup followed by plateau reduction), early stopping patience, and gradient clipping are all subject to hyperparameter optimization as described in \Cref{sec:hpo}.

\section{Hyperparameter Optimization}
\label{sec:hpo}

We use Optuna \cite{akiba2019optuna} for hyperparameter optimization. Optuna persists study state in an SQLite database, which allows interrupted searches to be resumed without loss of progress. As the sampler we use the Tree-structured Parzen Estimator (TPE), a Bayesian approach that models the distributions of hyperparameter values separately for well-performing and poorly-performing trials, then samples candidates that are more likely under the former. This lets TPE focus the evaluation budget on promising regions of the space, typically reaching competitive configurations within 150--200 trials even in large search spaces.

Grid search is impractical in our setting because the number of hyperparameters and their interactions make the combinatorial space too large to enumerate, and each trial requires a full training run. Beyond feasibility, even an exhaustive search would not guarantee reliable selection: a single run with a favorable random seed can produce a misleadingly high score. To address this, after each search phase we retain the top~10 configurations ranked by validation~F1 and re-evaluate each with 5~different random seeds. The configuration with the highest mean validation~F1 across these reruns is selected as the winner, guarding against configurations that scored well due to a lucky initialization.

\paragraph{Three-Pass Strategy.}
\label{sec:three-pass}
Because the full search space is large and parameter interactions are complex, we decompose the optimization into three sequential passes. Each pass searches a subset of parameters while fixing those selected in earlier passes. \Cref{tab:hpo-passes} summarizes the parameters optimized in each pass. To speed up the search, passes use a reduced training epoch budget; final evaluation retrains with the full epoch budget.

\begin{table}[!t]
\centering
\caption{Hyperparameters searched in each HPO pass. Values selected in earlier passes are fixed for subsequent ones.}
\label{tab:hpo-passes}
\begin{tabular}{clp{7cm}}
\hline
\textbf{Pass} & \textbf{Focus} & \textbf{Parameters} \\
\hline
1 & Loss weights \& data & Loss weights ($\alpha$, $\beta$, $\gamma$), window length, window stride, batch size; adversarial weight (Scenarios~4.x) \\
2 & Regularization & Learning rate, weight decay, warmup epochs, LR scheduler patience and factor, label smoothing, dropout rates (feature extractor, classifier, regressor) \\
3 & Model capacity & Convolution kernel sizes, filter counts per layer, embedding dimension, hidden layer sizes \\
\hline
\end{tabular}
\end{table}

Pass~1 targets loss weights and data parameters because these determine the optimization landscape before regularization or capacity considerations matter. Pass~2 tunes regularization and learning rate scheduling, which affect generalization and training stability. Pass~3 searches model capacity last, since optimal architecture size depends on the regularization regime established in earlier passes.

\paragraph{Final Evaluation.}
Once the three-pass HPO selects the best configuration, we evaluate it on the held-out test set. We train the winning configuration 10~times with different random seeds, each time using the full epoch budget. For each run, the model with the best validation~F1 is selected and evaluated on the test set. We report the mean and standard deviation of test~F1 across the 10~runs as the final result.
